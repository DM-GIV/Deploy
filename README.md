# Сайт Дмитрия Иванова — торги по банкротству

Статический многостраничный сайт, развёртывается на Vercel из ветки `main` репозитория `DM-GIV/Deploy`.

## Страницы

- `/` — короткая главная и воронка: выбор задачи → бесплатный инструмент → подготовка обращения → согласование работы
- `/proverka-lota/` — методика проверки и интерактивная карта конкретного лота
- `/poisk-imushchestva/` — поиск имущества и интерактивная карта запроса
- `/soprovozhdenie-torgov/` — этапы и ограничения сопровождения
- `/pokupka-imushchestva/` — полная стоимость и процесс покупки
- `/primery-lotov/` — четыре публичных примера с ссылками на АТЦ
- `/formaty-raboty/` — сравнение самостоятельного, индивидуального и сопровождаемого форматов
- `/blog/` — библиотека практических материалов
- `/blog/kak-proverit-lot-pered-torgami/` — общий чек-лист перед торгами
- `/blog/kak-proverit-avtomobil-s-torgov/` — проверка автомобиля, включая пример лота АТЦ
- `/blog/kak-proverit-zemelnyi-uchastok-s-torgov/` — проверка земельного участка

## Воронка

Пользователь выбирает маршрут на главной, переходит к форме, получает предварительную карту **без передачи контакта**. По отдельной кнопке формируется редактируемый текст обращения. Пользователь сам выбирает e-mail, Telegram или копирование. На сайте нет серверного приёма обращений, CRM и автоматической отправки сообщений.

Важно: карта проверки не загружает документы и не анализирует введённую ссылку; она формирует перечень вопросов. Фактическая проверка согласовывается отдельно.

## Ограничения и редакционная политика

- География услуг — вся Россия. Не позиционировать предложение через отдельный регион.
- Не заявлять о гарантированной прибыли, выигрыше или отсутствии рисков.
- Публичные лоты АТЦ — примеры исследования, **не сделки клиентов**. Начальные цены являются историческими.
- Не публиковать личные данные должников и неподтверждённые показатели.
- Перед изменением ссылок сверять цели `#lot-check-form` на /proverka-lota/ и `#search-brief-form` на /poisk-imushchestva/.
- Вносить изменения только в репозиторий `DM-GIV/Deploy`.

## Проверка перед публикацией

1. По одному H1, уникальные Title, Description и canonical для каждого URL.
2. Все внутренние ссылки и якоря ведут к реально существующим разделам.
3. Карты проверки и поиска работают в браузере; открытие Telegram/e-mail требует нажатия пользователя.
4. Мобильные карточки перестраиваются в одну колонку.
5. Sitemap содержит все основные индексируемые страницы.

## Контроль воронки и события

`assets/funnel-events.js` подключён на всех страницах сайта. События имеют общий `page_type`; скрипт не создаёт cookie, не пишет в localStorage, не отправляет запросы и не собирает контакты. Пока не подключена аналитическая платформа, `dataLayer` — только клиентский буфер событий и **не является статистикой посетителей**.

Карта контрольных событий:

- `funnel_page_open` — открыта страница (по типу страницы).
- `funnel_page_route` — переход к иной странице из меню или CTA.
- `lot_check_start` / `lot_check_complete` — начата/сформирована карта проверки.
- `search_brief_start` / `search_brief_complete` — начата/сформирована карта поиска.
- `lead_draft_prepared` — подготовлено редактируемое обращение.
- `lead_draft_copy` — текст обращения скопирован по действию пользователя.
- `lead_handoff_opened` — открыт Telegram или почтовый редактор (**не доказательство отправки обращения**).
- `funnel_contact_open` — переход к телефону, Telegram или e-mail из контактов.

Разрешены только заданные категории/источники событий; текст вопросов, URL лота, регион, бюджет, телефон и e-mail не передаются в данные аналитики. Реальную конверсию «получено обращение» следует измерять отдельно, в CRM/почте, а не при клике на ссылку.

**Следующая зависимость:** подключить принадлежащий владельцу сайта счётчик Яндекс Метрики или GA4 и проверить приём событий в нём. До этого статистические отчёты и утверждения о росте конверсии делать нельзя.
