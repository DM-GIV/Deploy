# Переход с учебного Vercel URL на постоянный домен

## Что остаётся прежним

- Репозиторий `DM-GIV/Deploy` и ветка `main`.
- Публикация через существующий проект Vercel.
- Восемь страниц и относительные внутренние ссылки.
- Формы проверки/поиска, страницы кейсов и стили.

Смена **домена** сама по себе не требует переноса сайта на VPS или создания нового проекта Vercel.

## Предварительные условия

1. Выбрать и зарегистрировать собственный домен. Не публиковать предположений о его доступности до проверки у регистратора.
2. В Vercel открыть проект → **Settings → Domains**, добавить домен и получить точные DNS-записи для него.
3. У регистратора прописать рекомендованные Vercel A/CNAME/TXT-записи (по обстоятельствам), подтвердить SSL и HTTPS.
4. Выбрать один канонический вариант (с `www` либо без); альтернативный должен перенаправлять на канонический.

## Изменить SEO-адреса в репозитории

В текущей статической версии учебный хост `https://deploy-pi-blond-52.vercel.app` встречается в:
- `rel="canonical"` каждой HTML-страницы;
- `og:url` и JSON-LD;
- `sitemap.xml`;
- `robots.txt` (адрес sitemap).

**Скрипт-помощник** в репозитории:

```bash
# Пример для ДЕМОНСТРАЦИИ. example.ru — фиктивный адрес.
node scripts/switch-domain.mjs --to https://example.ru

# Только после проверки и настройки реального домена:
node scripts/switch-domain.mjs --to https://example.ru --apply
```

Без `--apply` скрипт не меняет файлы. Он проверяет наличие исходного домена во всех 10 файлах и выводит план замен. Он **не** меняет DNS, настройки Vercel, поиск или редиректы.

## Проверка после подключения

1. Убедиться, что все восемь новых URL возвращают HTTP 200 с корректным HTML.
2. Проверить HTTPS, относительные CSS/JS и работу форм без подключения Метрики.
3. Проверить self-referencing canonical, Open Graph URL, Sitemap, robots.txt и Schema.org.
4. Настроить 301 со старого доступного адреса на соответствующий новый URL, насколько позволяет настройка доменов проекта. Не перенаправлять все старые страницы на одну главную.
5. Проверить, что учебный Vercel URL не конкурирует с основным адресом как дубль; при невозможности 301 использовать canonical и обсудить техническую конфигурацию отдельно.
6. Когда будем переходить к поисковому продвижению, добавить новый домен в Яндекс Вебмастер и Google Search Console; при уже индексированном старом домене использовать предусмотренные ими процедуры переноса сайта.
7. Подключать Метрику только отдельным решением.

**Важно:** учебный сайт сейчас технически доступен поисковым роботам (index,follow). Установку noindex, удаление из индекса или смену canonical до выбора нового домена не производим автоматически.

## Что не меняем заранее

- Текущий опубликованный URL.
- Никаких перенаправлений на пока несуществующий домен.
- Данные клиентов, документы сделок и события аналитики.

Официальные инструкции: Vercel — https://vercel.com/docs/domains/set-up-custom-domain ; Google — https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes ; Яндекс — https://yandex.ru/support/webmaster/ru/yandex-indexing/moving-site.html
