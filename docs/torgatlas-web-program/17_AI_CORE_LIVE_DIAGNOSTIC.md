# Диагностика расхождения публичного AI-поиска и Core-прототипа (2026-10-15)

## ROOT_CAUSE
Публичный сайт **не использует Core вообще**. Production работает в режиме `PUBLIC_WEB_RESEARCH_MINI` — прежнем живом обходе страниц площадок; код Core-поиска не развёрнут и не подключён:
1. Образ `auction-data004:auc163-fc6dbce` (aa-data004-api-1) не содержит `public_search.py`; в OpenAPI нет `/api/v1/public-search`, `GET /api/v1/public-search` → 404.
2. У `ai-search` нет `AI_LOT_CORE_URL`/`AI_LOT_CORE_TOKEN` → в коде `coreConfig(env)=null` → POST идёт в `publicResearchMiniSearch` (доказано логикой кода в запущенном контейнере и самими ответами: у карточек поле `region_code`, которого нет в Core-контракте).
3. Сеть: `ai-search` в internal-сети, до Core недостижим (127.0.0.1:18004 ECONNREFUSED, 100.65.166.71:18004 ENETUNREACH, aa-data004-api-1:8000 timeout).
Неверная выдача — свойства старого движка (`lib/torgatlas-public-web-research.mjs`): `parseSimpleQuery` ищет регион подстрокой из `REGION_NAMES` — для «в Москве» искомое `москва` не входит в `москве` ⇒ региональный фильтр не применяется вообще; тип — набор подстрок (`квартир`, `жилой дом`, …), «легковые автомобили» → `транспорт/автомобил/прицеп/грузов/спецтех` без различения; снегоход проходит по слову «транспорт». Прицепы ПФО: 0, потому что старый движок видит только каталоги нескольких площадок на момент запроса, а Core знает 4 лота ЕФРСБ.
