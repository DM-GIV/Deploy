# TORGATLAS-METRIKA-001: Яндекс Метрика (счётчик 113657048)

Статус: ПОДГОТОВЛЕНО, сбор данных ВЫКЛЮЧЕН (`METRIKA_ENABLED = false` в `assets/metrika.js`). Не развёрнуто.

## Что сделано
- `assets/metrika.js` подключён в `<head>` (с `defer`) на 21 публичной HTML-странице torgatlas.ru; код счётчика в одном месте, дублей нет.
- Официальный сниппет взят за основу, изменено ради приватности: URL и referrer уходят без query/hash (в query лежат ссылки на лоты), `trackLinks:false`, Вебвизор и ecommerce не включены.
- `<noscript><img>` НЕ используется: он обращался бы к mc.yandex.ru без согласия.
- Загрузка только после отдельного согласия (`ta_metrika_consent`, отдельно от Umami); GPC/DNT = ноль запросов.
- Новое событие воронки `lead_direct_started` (первый фокус в прямой форме заявки, один раз на форму).
- admin/api/app.torgatlas.ru не затронуты: код только в статике основного сайта.

## БЛОКЕРЫ включения (решение владельца)
1. Политика конфиденциальности (разд. 9, п. «Яндекс Метрика не подключена», «cookie не используются», «данные не передаются третьим лицам») и текст баннера нужно переписать: Метрика ставит cookie и передаёт данные ООО «Яндекс». Нужны правовая модель согласия и проверка соответствия уведомлению в Роскомнадзор (подача 100456724) — юридическое решение, не техническое.
2. В Метрике владельцу: отключить Вебвизор, проверить, что не включены лишние функции; создать цели из таблицы.
3. CSP сейчас в проде не применяется; в шаблоне `ops/security/*.example` добавлены mc.yandex.ru и yastatic.net без `unsafe-inline`.

## Включение
Изменить флаг на `true`, `python3 scripts/fingerprint-assets.py`, релиз по обычному порядку, затем проверка `?_ym_debug=2` и отчётов Метрики (Вебвизор выкл., цели приходят).
