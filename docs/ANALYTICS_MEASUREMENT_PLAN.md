# ТоргАтлас — план веб-аналитики

Дата подготовки: 12.10.2026.

Статус: IMPLEMENTATION_READY / COUNTER_ID_PENDING. Пока `COUNTER_ID = 0`, Яндекс Метрика не загружается и статистика не собирается.

## Основные цели

- `lot_check_complete` — пользователь сформировал предварительную карту проверки лота.
- `search_brief_complete` — пользователь сформировал карту запроса на поиск имущества.
- `lead_handoff_opened` — пользователь открыл ручной канал передачи подготовленного обращения. Это **не подтверждение получения заявки**.
- `funnel_contact_open` — пользователь открыл телефон, ТГ, MAX/e-mail контакт в интерфейсе.
- `lead_direct_accepted` — резервная цель для будущего P3. Считать реальной заявкой только после серверного ответа ACCEPTED; до включения P3 не использовать в отчётах как конверсию.

## Ограничения приватности

В Метрику передаётся только имя цели из жёсткого allowlist. Не передавать URL лота, контакт, телефон, e-mail, бюджет, текст обращения, регион пользователя или произвольный `event.detail`.

Вебвизор выключен. Провайдер загружается только после явного согласия. GPC/DNT блокируют загрузку.

## Активация

1. Владелец создаёт счётчик Яндекс Метрики для `https://torgatlas.ru` и передаёт только числовой ID счётчика.
2. Отдельный минимальный PR заменяет `COUNTER_ID = 0` на подтверждённый ID.
3. До production release обновить фактическую формулировку `/privacy/` с «не включена» на описание реально включённой consent-gated Метрики.
4. В кабинете Метрики создать JavaScript-цели с именами из списка выше.
5. Browser/network acceptance: до consent нет запросов к mc.yandex.ru; после accept есть tag.js и test goal; после decline запросов нет; GPC/DNT блокируют; webvisor не активируется.
